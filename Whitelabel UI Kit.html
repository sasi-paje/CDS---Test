Getting started

A brand-agnostic design system built from semantic tokens. Switch the theme or brand hue above — every component reflows. Drop the CSS into your project and import the React primitives.

For designers & engineers

How to design with this kit

  1. Never use raw values. No hard-coded hex, px, or ms. Always reach for a token — var(--fg-default), var(--space-5), var(--radius-md). If a token doesn’t exist for what you need, add one to tokens.css rather than inlining.
  2. Consume the semantic layer, not the scale. Use --fg-muted, not --neutral-500. Use --bg-brand, not --indigo-600. Only the tokens.css file should reference primitive scales.
  3. One brand, one accent. The brand hue is set on <html data-brand="..."> and re-aliases the entire --brand-* scale. Don’t introduce a second accent color — pick a variant (Badge, Alert) that already uses success/warning/danger/info if you need a second hue.
  4. Pick the right variant for the right action. Primary = single most important action per surface. Secondary = supporting. Outline / Ghost = tertiary. Danger = destructive only. Link = inline in text.
  5. Match size to context. xs/sm for table rows and toolbars; md for forms and page actions (the default); lg for landing CTAs and empty states.
  6. Respect spacing rhythm. Most layouts only need 4 / 8 / 12 / 16 / 24 / 32. Avoid breaking the 4-point grid.
  7. Check contrast. Any text pair must hit at least AA (4.5:1) — see the Contrast section. Tinted backgrounds (--bg-*-subtle) are paired with their matching --fg-* for AA-safe combinations.
  8. Light + dark are equal citizens. Test every screen in both. Components do this automatically because they consume semantic tokens, but custom CSS you add must do the same.
For Claude & other LLMs

How to build with this kit

When generating UI for this project, follow these rules verbatim. They keep output consistent with the system and avoid the most common mistakes.

  • Always import tokens first: <link rel="stylesheet" href="src/whitelabel/tokens.css" /> and set <html data-theme="light" data-brand="indigo">.
  • Always import Primitives before any custom component: <script type="text/babel" src="src/whitelabel/Primitives.jsx"></script>. Available globals: Button, IconButton, Input, Textarea, Select, Checkbox, Radio, Switch, Badge, Avatar, AvatarGroup, Card, Spinner, Alert, Tooltip, Progress, Tabs, Breadcrumbs, Kbd, Icon.
  • Use semantic tokens only. Forbidden inline values: hex codes, named colors, raw px for spacing/radius. Allowed: var(--fg-*), var(--bg-*), var(--border-*), var(--space-*), var(--radius-*), var(--shadow-*), var(--text-*), var(--dur-*), var(--ease-*).
  • Map intent → variant:
      • Confirm/save/submit → Button variant="primary"
      • Cancel/back/secondary action → Button variant="secondary" or "outline"
      • In-table or icon-bar actions → Button variant="ghost" + iconOnly
      • Delete/destroy → Button variant="danger" with a confirmation step
      • Inline in copy → Button variant="link"
  • Map intent → status: success / warning / danger / info — never invent a 5th. Badge, Alert, Progress all share this taxonomy.
  • Form fields: always set label and either placeholder or hint. Errors must use error + hint together. Required fields get required.
  • Accessibility minimums:
      • Any iconOnly button needs ariaLabel
      • Status communicated by color must also use an icon or text
      • Touch targets ≥ 32px (use size md by default)
      • Verify pair contrast against the Contrast section
  • Layout primitives: Card for grouping content; Tabs (underline) for top-level views, Tabs (pill) for inline scoping; Breadcrumbs for nav location; Tooltip for icon-only buttons.
  • When in doubt: open the spec card for the component in this kit and copy the source. Every spec has a working JSX example.

Quickstart

<!-- 1. Include tokens -->
<link rel="stylesheet" href="src/whitelabel/tokens.css" />

<!-- 2. Theme & brand on <html> -->
<html data-theme="light" data-brand="indigo">

<!-- 3. Use semantic tokens in your CSS -->
.my-card {
  background: var(--bg-raised);
  color:      var(--fg-default);
  border:     1px solid var(--border-subtle);
  box-shadow: var(--shadow-sm);
  padding:    var(--space-6);
  border-radius: var(--radius-lg);
}

<!-- 4. Or use the React primitives -->
<Button variant="primary" leading="plus">Create</Button>
<Input label="Email" leading="mail" required />
<Alert variant="success" title="Saved">Your changes were synced.</Alert>

Color palettes

11-step scales tuned for accessibility. brand-* is an alias that re-points to one of the hue families based on [data-brand] — pick a swatch above to swap.

Semantic tokens

The layer you actually consume. Backgrounds, foregrounds, borders and status colors. Every value changes automatically between light and dark themes.

Contrast (WCAG AA / AAA)

Computed contrast ratios for common foreground/background pairs in the current theme. AAA ≥ 7:1, AA ≥ 4.5:1 (normal text), AA-L ≥ 3:1 (large text), FAIL < 3:1.

Typography

Single family (Inter) covers headings + UI. 10-step scale and a small set of semantic classes.

Spacing

4-point base, 8-point harmony. Use named tokens — never raw pixels.

Radius

Default to --radius-md (6px) for buttons and inputs; --radius-lg (8px) for cards.

Shadows

Five-step elevation, plus an inner shadow for pressed/inset surfaces.

Motion

Three durations and four easings. Hover over the demo squares to see them.
