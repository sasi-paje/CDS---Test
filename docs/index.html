Whitelabel Design System

A brand-agnostic UI kit built on semantic tokens. Swap brand hue, theme, and style on <html> — every component reflows with no rebuild.

What's included

  • 12 brand hues — indigo, violet, fuchsia, pink, rose, red, orange, amber, emerald, teal, cyan, blue
  • Light + Dark themes — applied automatically via CSS variables
  • 5 style presets — Standard, Enterprise, Friendly, Refined, Data-dense
  • 50+ components — Button, Input, Badge, Dialog, DataTable, Sidebar, and more
  • Semantic token layer — colors, spacing, typography, shadows, motion, z-index
  • WCAG AA accessibility — contrast, ARIA, keyboard navigation built in

Core principles

Token-driven
All styling via CSS variables. Change colors, not code.
No build required
Works in any browser with React, Babel, and Lucide from CDN.
Composable
Mix and match components. Simple primitives, complex layouts.
Accessible
WCAG AA contrast, proper ARIA, keyboard support built-in.

Getting started

Quick start

No npm install, no build step. Load tokens, React, and component files — write JSX directly in the browser.

<!doctype html>
<html lang="en" data-theme="light" data-brand="indigo" data-style="standard">
<head>
  <link rel="stylesheet" href="src/whitelabel/tokens.css" />
  <script src="https://unpkg.com/react@18.3.1/umd/react.development.js"></script>
  <script src="https://unpkg.com/react-dom@18.3.1/umd/react-dom.development.js"></script>
  <script src="https://unpkg.com/@babel/standalone@7.29.0/babel.min.js"></script>
  <script src="https://unpkg.com/lucide@latest"></script>
</head>
<body>
  <div id="root"></div>
  <script type="text/babel" src="src/whitelabel/Primitives.jsx"></script>
  <script type="text/babel">
    const { Button, Card, Input, Alert } = window;
    function App() {
      return (
        <Card>
          <Alert variant="success" title="Ready">Design system loaded.</Alert>
          <Input label="Email" placeholder="you@example.com" />
          <Button variant="primary">Get started</Button>
        </Card>
      );
    }
    ReactDOM.createRoot(document.getElementById("root")).render(<App />);
  </script>
</body>
</html>
Three attributes control everything. Set data-theme, data-brand, and data-style on <html> — the entire interface reflows with no code changes.

Components

Buttons

The primary action component. Use variant to communicate intent. One primary per surface.

Variants

Primary Secondary Outline Ghost Danger 
<Button variant="primary">Primary</Button>
<Button variant="secondary">Secondary</Button>
<Button variant="outline">Outline</Button>
<Button variant="ghost">Ghost</Button>
<Button variant="danger">Danger</Button>

Sizes

Small Medium Large 
<Button size="sm">Small</Button>
<Button>Medium (default)</Button>
<Button size="lg">Large</Button>

When to use each variant

  • primary — the single most important action per surface
  • secondary — supporting actions (cancel, back, reset)
  • outline — secondary actions that need more visual weight
  • ghost — toolbar, table row, and icon-bar actions
  • danger — destructive actions only; always confirm first

Components

Badges

Inline status indicators. The taxonomy is closed — four semantic variants plus neutral and brand.

Active Pending Failed Processing Draft New 
<Badge variant="success">Active</Badge>
<Badge variant="warning">Pending</Badge>
<Badge variant="danger">Failed</Badge>
<Badge variant="info">Processing</Badge>
<Badge variant="neutral">Draft</Badge>
<Badge variant="brand">New</Badge>

Status must be communicated by color and text (or icon). Never rely on color alone.

Guidelines

Usage rules

Ten rules for every screen and every component. Written into CLAUDE.md so Claude Code follows them automatically.

1
Never inline raw values
No hex colors, no raw px for spacing or radius. Use tokens: var(--fg-default), var(--space-4), var(--radius-md).
2
Consume the semantic layer, not the scale
Use --fg-muted not --neutral-500. Use --bg-brand not --indigo-600.
3
One brand, one accent
Never introduce a second hue alongside --brand-*. A second color must be success / warning / danger / info.
4
Variant maps to intent
One primary per surface. danger always confirms. ghost for toolbars.
5
Match size to context
xs/sm for tables. md for forms (default). lg for landing CTAs.
6
Status taxonomy is closed
Exactly: success, warning, danger, info. Never invent a fifth variant.
7
Light and dark are equal
Test every screen in both themes. Components get dark mode free via tokens.
8
Accessibility floor: AA
4.5:1 contrast. Touch targets ≥ 32px. Icon-only buttons need ariaLabel.
9
Form fields need labels
Always set label. Errors = error + hint. Required fields get required.
10
Respect the spacing rhythm
4-point grid. Most layouts: --space-3/5/7/8 (8/16/24/32px).

Building your own

  1. Create a folder: examples/my-page/
  2. Copy the Quick Start boilerplate above
  3. Use only components from src/whitelabel/
  4. Test in both light and dark themes
  5. Push to Git when ready
